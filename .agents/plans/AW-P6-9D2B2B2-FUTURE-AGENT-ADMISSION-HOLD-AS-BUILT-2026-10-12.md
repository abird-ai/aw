## 1. Exact Source/Effect and noninterrupting Control contract

1. **Only optional trusted original Host enrollment:** `aw::model_agent_control::install_pause_after_turn(&Service,&mut original Agent)` requires the same current authenticated 9C original `actor_owner::Service` and original journaled Agent. That Actor's immutable Envelope must **already** contain the exact `Host/trusted-host/epoch1/Write` grant specifically named `agent_pause_after_turn`. A model/provider/project/extension/remote peer, D1 `agent` Read, D2 Process Write, another SourceKind, or a forged writer/epoch/ActorKey cannot create this grant. The original trusted host then installs one original `ToolEffect::Write` entry through `Agent::register_host_tool` / `ToolPolicy` with original source/effect/site bounds. The new Tool is **OFF BY DEFAULT** in ordinary CLI, R12/stdio, TUI, Web and signed AwNet/MachineLink; external JSON cannot invoke the host-only install API.
2. **Exact model JSON:** Tool name `agent_pause_after_turn`, arguments precisely `{"op":"pause_after_turn"}`. No other fields, target, process ID, child Actor, provider/account, principal, message source/sequence, writer epoch, freeze/cancel action, future clock time, reactivation token or human approval. The host gets all authority and intent correlation exclusively from the original trusted `ToolContext`. The model Tool validates both provider schema and semantic exactness, then calls `Service::request_model_pause_after_turn`, which independently verifies the actual live original principal+Session/branch+site, original Actor generation+WriterEpochFence, selected provider/payer/credential, uncancelled **currently active original Runtime Turn** and exact immutable SQLite `actor.input Dispatching` accepted Input. It rechecks the specific **Write** Envelope name/effect before and after the durable write. No direct Runtime Control Message or paid effect is generated by the pause Tool.
3. **Safe original current-Turn settlement:** The model may request a pause *while its own real original paid Turn is executing*, but the original provider, Tool batch and immutable ToolStarted/ToolFinished/Turn journal remain **UNINTERRUPTED**. The ToolOutput truthfully reports `kind:"original_agent_future_admission_hold"`, state Armed, `scope:"AFTER_CURRENT_ORIGINAL_TURN"`, `current_turn_interrupted:false`, future admissions `HELD`, `release:"EXPLICIT_AUTHENTICATED_OWNER_ONLY"`, and `retry:"NEVER_AUTOMATIC"`. This is **not** claiming Actor `FreezeActor` or a ControlKind::Freeze applied to an ongoing Runtime mailbox. It is one new original **admission fence** scoped to the host-owned **Session+branch**, not a universal freeze of other Agents or plain unbound Agent APIs.
4. **Immutable existing v33 owner/writer audit:** `aw-store::model_agent_pause` is a small derived service using existing `audit` and `security_audit_events`, no new SQLite tables/migrations. An original `ModelAgentPauseRequest` has a host-minted stable per-original Session+branch+Turn **`ap_` SHA256 ID**, domain-separated from D2A/B1 `mq_`/`md_` and Process `mp_`. SQLite `BEGIN IMMEDIATE` validates current original **active** WriterEpoch, Session owner, branch, original **`runs.status='running'`** / matching original writer/Turn, immutable `actor.input Dispatching` sender/recipient/Session/branch/source Turn. It appends exactly one typed `actor.model.future_pause` **Armed** fact, without payload or secret ref. Duplicate/retried same ToolCall/Turn IDs, forged IDs, wrong owner/epoch/source, another outstanding Armed fact and log exhaustion fail closed; an Unknown previous request never supplies a reset token or silently creates another Tool effect. The bounded audit limit is 4096 facts; source identifiers and Note (only on release) are typed/sanitized; no private model text/queue payload/provider secrets in this audit.
5. **Protect the real original Input/Queue transaction boundaries:** `actor_admission::actor_input_prepare` and `actor_queue::actor_queue_claim_next` check the exact current Session+branch **future admission hold inside their existing `BEGIN IMMEDIATE` transaction** before appending Input Prepared or irreversible Queue Claimed facts. That includes direct original Store callers, not just `Service::submit`/`admit_next_queued`. A blocked queued item remains immutable **Pending** with its original encrypted private `LocalSecretStore` blob intact and is not automatically executed/replayed. An authenticated host may still place independently authorized future **Pending** items while held; the hold prevents admission/claim/provider execution, not original storage of user intent. There is no new scheduler or extra model/Agent loop.
6. **Release requires authenticated current owner and factual settlement:** Only host-side `Service::release_future_pause(&original Agent, exact_intent_id, printable_note)` can append the typed **Released** fact after verifying the current real owner/writer+Actor generation, SAME original journaled Agent, and complete idle/reconciled in-memory owner state. Store `model_agent_pause_release` checks original current owner/writer+branch, exact Armed ID, no active run, **the initiating original `actor.input` MUST be FACTUALLY `Settled`**, no other original Input facts requiring inspection, printable bounded nonempty note, and a unique original audit transition. It appends the Released fact in the same current SQLite v33 writer transaction. Wrong users/epochs/IDs, model attempts, `Prepared`/`Accepted`/`Dispatching`/`Unknown`/`Inspected` initiating Input, duplicate release or another outstanding uncertain Input are DENIED. Released does **not** override a separate unresolved paid provider/Tool/Control hazard. This is an **authenticated owning-host decision**, not a newly implemented OIDC/browser/human-guardian approval.
7. **Power loss/restart and no-replay:** A previously Armed hold remains active after the store process closes/reopens and after Actor Runtime reattachment to the same originally authorized Session/branch/current writer. If the originating paid Turn is still Unknown after the crash, the hold remains **inspection-required and not releasable by this API**; restoring a process is never proof of model settlement. If the originating Turn had actually settled before the crash, an independently current authenticated owner may append one Released audit fact after source verification and future original Input admission can then proceed. Duplicate `pause_after_turn` Tool proposals in one original Write batch may leave one Armed fact and original `Agent`/Turn **Unknown**, not a fabricated success or a permissible retry. No automatic resume after restart, no replay of the original paid Turn, no model-origin user approval or arbitrary Actor/OS signal.
