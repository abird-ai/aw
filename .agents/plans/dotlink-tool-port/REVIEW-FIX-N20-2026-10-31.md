## Eight sequential fresh review/fix passes

1. **Checkpoint identity, cursor, settlement.**
   A cloned File shares kernel seek offset on Unix; checkpoint hashing
   could move an existing spool reader. Replaced clone/seek/read with
   offset-based FileExt reads on Unix/Windows. Checkpoint creation and
   validation now reject Queued/Running task states. Regressions cover
   shared-cursor immutability and unsettled snapshots.
2. **Journal ambiguity.**
   A persistence callback could commit an external CAS then return a
   non-special error; the local TaskFence previously stayed live and
   allowed retry. Every ambiguous callback error now fences further
   operations as JournalOutcomeUnknown. Only explicitly proven
   JournalRejectedNoEffect remains retryable. TaskTransition carries
   the immutable task-binding fingerprint. Tests cover both branches
   and keep local generation unchanged on failed CAS.
3. **Retention lease linearity.**
   A non-Copy cleanup authority could be minted repeatedly from one
   immutable lease. CleanupAuthority now exclusively borrows its
   RetentionLease; confirmed disposal marks the persisted lease
   released and subsequent cleanup requests are rejected. Failed
   disposal remains retryable; the original host must still enforce
   authoritative durable CAS across independently restored leases.
4. **Typed media host panic.**
   Panicking media policy callbacks now fail closed. Panicking
   attachment callbacks return DeliveryUnknown because provider bytes
   may already have been delivered; no implicit retry or provider
   action is introduced. Regression verifies both paths.
5. **Spool reservation transfer on accounting errors.**
   The prior reservation counted successful OS writes as transferred
   before StreamSummary could accept them. If accounting later failed,
   the reservation could leak quota. Capacity transfers to the RAII
   retained owner only AFTER successful StreamSummary accounting;
   failed/partial paths return all untransferred reservations.
6. **Process callback and impossible snapshot guards.**
   Host-supplied source and cancellation callbacks are caught at the
   AW Process host adapter boundary: source panics deny access, and
   cancellation panics produce CancelOutcomeUnknown (signal/effect
   might already have happened). Completed checkpoints with failed
   persisted output are rejected; no false completed receipt.
7. **Adversarial stream accounting/property regression.**
   Tested 128 bounded deterministic chunk/quotas combinations,
   checking source totals, retained exact prefixes, irreversible
   truncation, capacity ownership and drop cleanup. No additional
   confirmed correctness defects in the final scoped audit.

8. **Ambiguous media attachment errors.**
   An attachment may deliver bytes to a provider before returning an error.
   Previously a normal host error looked like a deterministic failure;
   both host errors and panics now return DeliveryUnknown, preserving
   optional diagnostic detail without inviting unsafe automatic replay.
   Added a host-after-send error regression.

## Architecture and safety

- aw-tools-core remains sync-default, transport-neutral; durable and
  sandbox features are opt-in. AW retains the one original Agent,
  exact source/site/effect grants, Process ownership and TurnJournal.
- The host owns persistent spool-file cleanup, journal reconstruction
  and exclusive recovered-file capability; validated checkpoint
  digests are not independent evidence of grant authority.
- Remote model-facing job APIs, native typed ContentBlock attachment,
  sandboxed Process registration and dotlink consumer integration
  remain separate authorized host projects; no duplicate database,
  new shell permission or job executor added.
- Windows GNU compilation is not native NTFS runtime validation.
  Linux Bubblewrap runtime remained blocked by host /proc mount EPERM.
