Ten implementation checkpoints, sequential with targeted source tests:

1. **N11 — Journal-first task transitions.** Separate verified transition
   *proposal* from irreversible commit, so in-memory generation cannot
   advance before the host proves durable CAS/journal settlement.
2. **N12 — Recoverable spool checkpoint.** Bounded versioned snapshot of
   the writer-quiesced spool including exact file identity/length/digest and
   factual delivery/ACK metadata; fail closed on corrupt/stale records.
3. **N13 — Safe host-handle spool recovery.** Recover from already-open
   verified handles and a host-validated checkpoint without new files,
   path authority, task IDs or an independent database.
4. **N14 — Host-owned retention lifecycle.** Explicit expiry/release policy
   and ownership transfer. Expiry cannot erase running or unsettled work.
5. **N15 — Host task operations.** Bounded get/list/output/ack/cancel
   command contracts with exact binding and generation checks; no implicit
   model-facing grants or new TaskRegistry.
6. **N16 — AW Process bridge.** Bind shared operations to existing
   FencedProcessSpools/Process supervision with no new effect executor.
7. **N17 — Media delivery contracts.** Complete-byte/media-kind checks,
   policy-declared transport ceiling and immutable attachment receipts,
   preserving native encoded JSON until provider-native support exists.
8. **N18 — Sandbox host lifecycle.** Fail-closed launch attestation,
   cancellation/exit evidence and mount-authority tests; no automatic
   promotion of trusted Bash to sandboxed.
9. **N19 — API and performance consolidation.** Remove duplicated hot
   loops/unnecessary allocation, guard resource ceilings and document
   public sync/async/durable/sandbox feature surfaces.
10. **N20 — Fresh audit and verification.** Targeted adversarial review/fix,
    Linux/Windows source and original-lock tests, CLI and no_std where
    feasible. Record exact completed/partial/blocked evidence.

All source algorithms default sync; async/durable/sandbox remain opt-in.
One original Agent/ToolRegistry/ToolPolicy/TurnJournal, exact actor/source/
site/effect and revocation boundaries. A host-local task interface is NOT
an automatically advertised model tool or transport. No schema/version bump.

## Executed phases and results

- [x] TS-N11 journal-first task transitions: shared TaskTransition proposal
  is pure, host journal/CAS persists before local generation changes.
  Ambiguous/panicking persistence fences all future operations until
  original host journal inspection. Non-journaled production shortcut removed.
- [x] TS-N12 versioned SpoolCheckpoint: binds source/task fingerprint,
  intent sequence, generation, disposition, pinned file identity, exact
  length/SHA-256 and StreamSummary delivery/ACK; corrupt or stale fails.
  Windows recovered-file R/W preflight no longer writes over existing data.
- [x] TS-N13 handle-based recovery: BoundedFileSpool::restore_verified takes
  a host-opened file, verified terminal checkpoint, and exact source
  generation; recharges session capacity, preserves delivery/ACK, and
  refuses corruption, unsettled states or insufficient quota.
- [x] TS-N14 retention policy: validates terminal, non-uncertain checkpoint
  and deadline, source/journal generation, writer quiescence. Cleanup
  authority is non-Copy with private fields; host disposal must be
  confirmed before release, with no hidden file deletion/sweeper.
- [x] TS-N15 bounded HostTaskOperations: Inspect/List/Output/Acknowledge/
  RequestCancel contracts, page limits, exact binding, generation,
  live source and duplicate list checks. This is NOT an advertised
  model tool or independent task database.
- [x] TS-N16 AW FencedProcessSpools bridge: host-supplied source-liveness
  rechecked at each operation; exact Process owner provides any
  cancellation callback. No second process runner or journal.
  Source callbacks run outside fence locks to avoid host reentrancy
  deadlocks. Production transitions require journal callbacks.
- [x] TS-N17 typed media delivery policy: MIME allowlist, bounded size,
  complete-byte digest/signature recheck, typed host consent. Receipt
  only after host attachment succeeds. Native bread still sends
  encoded JSON rather than provider-native ContentBlocks.
- [x] TS-N18 Linux sandbox contract: pinned runtime/workspace/binary
  descriptors, no nested user namespaces, checked nonzero launcher
  exit, RAII child owner. Host must journal Process intent; no new
  default sandbox grant. Actual l5 namespace run remained blocked
  by the host's /proc mount EPERM.
- [x] TS-N19 shared stream accounting: one irreversible, checked
  StreamSummary::record_chunk for retained source prefix across normal
  writes, exhaustion, failures and compaction. No future bytes may
  overwrite a missing source segment, even after quota reclamation.
- [x] TS-N20 adversarial review: rejected uncertain task expiry,
  malformed checkpoint-derived retention claims and duplicate task
  list entries; removed non-journaled transition APIs; fixed source
  callback reentrancy and panicking/ambiguous durable commits.
