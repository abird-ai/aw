## 3. Minimal original owner-only publication and failure boundaries

**R implementation method:** private `PartialCapture::publish_complete(self, &original_owner_SessionStore, final_name, private_test_boundary) -> Result<PathBuf>`, compiled only on **Linux** using the actual kernel `renameat2(AT_FDCWD, old, AT_FDCWD, new, RENAME_NOREPLACE)` via a contained documented `unsafe extern "C"` FFI call. This is not the ordinary `std::fs::rename`: the latter can REPLACE an existing empty directory, and an earlier `symlink_metadata()` precheck alone is vulnerable to check-then-rename races. The `RENAME_NOREPLACE` kernel decision is the final atomic guard, even if another cooperating process creates the basename in the private parent after a precheck. Linux syscall failure (including `EEXIST`, cross-mount `EXDEV`, unsupported kernel/FS) is a fail-closed original error with no overwrite fallback. **Native macOS/Windows/ARM publication implementation remains DISABLED** pending independent OS-specific no-replace/ACL+fsync evidence. Internal Linux source is not intended as a cross-platform user-facing API.

Publication steps under the existing original owner (after P/Q capture already obtained/released its own original N/O lease): (1) confirm exact current original Store/process/store_id/generation, strict basename/private parent and original P/Q staged proof; (2) create a **new** owner-only `manifest.json` with stable complete V1 fields and original staged `restore_generation`, exact file receipt list, `complete=true`; fsync file; (3) remove ONLY that stage's `manifest.partial.json`, fsync the stage directory, then independently reverify the staged V1 complete payload while it is still unpublished; (4) run the Linux `renameat2(RENAME_NOREPLACE)` atomically within the private parent (no existing directory/file/symlink may be overwritten); (5) **IMMEDIATELY disarm only the original `PartialCapture` RAII cleanup AFTER the kernel rename succeeds**; (6) fsync the renamed directory's parent, reverify the named complete archive, then return success. Any failure BEFORE rename removes only the self-created ephemeral stage and preserves all previous operator backups/original Store bytes. After rename success, **even an injected hook error or a parent fsync failure MUST NEVER delete the newly named artifact**; report the failure/durability uncertainty to the original owner and leave its complete-format bytes for explicit inspection. The parent fsync must complete before successful durable-publication response. This avoids a dangerous "write was successful then error cleanup deletes it" pattern, as established by AW-P6-10K/L.

The `private_test_boundary` callback is NOT an exposed extensibility Hook/agent operation. It exists solely inside an unreachable-from-shipping-source private module to produce deterministic failures at `BeforeRename` and `AfterRenameBeforeParentSync`, and real process exit cases with no Rust destructor/SQL lease release. The original capture file, SQLite and SecretStore write barriers and original no-replay remain unchanged. The new `PartialCapture` internal `published` flag is set true **only after** `renameat2(NO_REPLACE)` succeeds; `Drop` never removes an already named complete owner artifact. This private v1 proof is a coherent file/credential-content snapshot, NOT a signature of its remote origin nor permission to start a recovered Agent or pay a provider.

## 6. Unresolved security and product/release gates

1. **NO SHIPPING RESTORE:** The v1 completed private directory is an operator-sensitive file artifact whose contents are now internally source-independently verifiable after successful atomic publish. It is **NOT YET a user-facing `aw backup --all` command nor a safely restorable SessionStore**. No code accepts the completed bundle into a live owner or starts an Agent from it. Offline restore needs a dedicated native review of empty owner-private destination, identity/generation CAS, correct original WriterEpoch/Actor/source/Process fencing, original incomplete paid/Tool/OS attempts, current encrypted custody, no replay of queued Input, and missing/mismatched/traversal/symlink/old-key negatives BEFORE any activation. The existing SQLite-only `SessionStore::backup(path)` API remains unchanged and must not be confused with this R-internal protocol. Future release must not silently call a copied encrypted queue a ready command.
2. **Publication durability:** `renameat2(RENAME_NOREPLACE)` on the same validated private filesystem and parent fsync after success provides a narrow Linux kernel-atomic no-overwrite contract. The deterministic **real process exit** tests at pre-rename and post-rename boundaries are NOT a natural power-loss, filesystem crash-recovery, kernel malicious-process, cross-filesystem, distributed-store or hardware write-cache/fsync certification. A parent fsync failure leaves an operator-inspectable named completed artifact but reports failure/durability uncertainty; never delete existing backups or silently retry write/publish operations.
3. **Privacy / origin:** File SHA-256 checksums, SQLite `quick_check` and original AEAD under a key **copied into the same directory** are corruption/coherence checks, NOT a signer-authenticated remote/source provenance or encrypted cloud archive. Publication does not grant any model/extension/remote Actor/human-origin capability and does not authorize transferring a bundle to untrusted external services.
