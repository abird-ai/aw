## 1. Unchanged normative architecture

- Exactly four core primitives: **Runtime, Actor, Message, Envelope**. Only two Hook verbs: **Next, Defer**. The sole original `Agent`, `ToolPolicy`, `TurnMachine` and immutable `TurnJournal` own model/tool/effect execution. Existing SQLite **v33** `audit`, Input/Control/Queue/Notice facts and private encrypted `LocalSecretStore` remain authoritative; no second model loop, work bus, Shell access grant, Hook runner, durable Control replay, JSONL format migration or extra actor/payer registration.
- **9C1 stays local and explicit:** `aw rpc --agent-stdio --agent-actor-owner --session-id EXISTING` creates only an OS-host-minted current Runtime/Actor binding, active Workspace writer epoch, exact Session+branch/site+Envelope and tools OFF. Ordinary R12 Actor operations remain denied by default. `actor_enqueue` stores private encrypted pending Inputs; `actor_step` claims at most one original Agent Turn; `actor_query`/`actor_op`/`actor_notice_read` have strict purpose-limited projections. A lost stream is never a reason to recreate an unknown paid attempt.
- **9C2 adds two bounded transports, not a second execution engine:** (1) the original headless reader now permits *typed `actor_op` Control* to be applied while the same original owning Agent runs through `actor_step`; (2) an opt-in, signed AwNet `MachineLink` QUIC connection supplies a remote session/branch-bound input/query/inspect/step/control/Notice-read gateway to that **same** owner and Agent. No raw client ActorKey, epoch, principal, session-owner, `allowed-tools` or runtime label has authority.

## 2. Exact 9C2 identity and security design

1. **Pairing and transport identity:** Existing AwNet Ed25519 key/Node ID pairing, QUIC peer certificate verification, signed MachineLink challenge/response, short-lived signed `lease_id` and explicit intersection of typed `ActorQuery`, `ActorInspect`, `ActorEnqueue`, `ActorStep`, `ActorControl`, `ActorNoticeRead` capabilities. Neither peer trust nor MachineLink alone authorizes Actor operations; `FileRead`, `GitRead`, `Pty`, shell, extension, session control, device credentials and `RemoteSessionExecute` remain independent and cannot be inferred from a new Actor capability. Signed lease requests and responses bind exact `lease_id`, random request correlation, Session ID and branch ID; unrecognized fields, mismatched protocol version, stale leases, oversize frames and duplicate request IDs fail closed.
2. **Additional explicit owner grant in SQLite v33:** New `actor.peer_grant` immutable `audit` facts, keyed to the precise owning Session/branch/site, peer Node ID **and its verified Ed25519 public key and security epoch**, current Workspace writer epoch, operation permission set and expiry (5–3600 seconds). A grant is explicit, owner-created, maximum 32 active/4096 immutable facts per Session, and may be terminally revoked by append-only fact; no permission is silently revived by restarting the process. `authorize_actor_peer` rechecks the exact Session owner, local active writer epoch/node, branch, current peer trust/key/security epoch, grant expiry and allowed operation *on every incoming network request*. Query permission does not grant Inspect, Enqueue, Step, Control or private Notice reading. An authorized `Step` rechecks the grant and original Actor binding approximately every 150ms while the provider is in flight. Signed MachineLink expiry independently fences a running Step; successful private results are also reauthorized **immediately before they are returned** to the signed peer.
3. **Original current-Turn Control:** For local R12 the independent bounded input reader examines **`actor_op` with an exact `{op:"control",request_id,message_id,action}`**, then asks the single `Service::control` to prove *current active* and exact Input/Turn/Actor generation/Session/WriterEpoch, persist `Prepared`, invoke original Runtime Control and append `Applied | Rejected | Unknown`. `CancelTurn` cooperatively cancels the same provider future through the existing cancellation token, never establishes paid/effect settlement or a tool result. There is **no** separate `actor_live_control` protocol alias; `actor_op` remains the canonical typed operation. When no Turn is genuinely active, Control is refused instead of being pre-armed. Freeze/Resume semantics use the original Runtime state and narrower exact Control audit. On QUIC, a concurrently negotiated Control stream under the same lease reaches the same `Service::control`, with no parallel Agent instance.
4. **Explicit locally owned live revocation:** The server holds `owner.lock` exclusively. A second `aw net actor-peer-revoke` process cannot directly acquire its store during a live server; it may be used *between* server runs. To revoke an **already negotiated** peer or running Step, the explicitly launched current server accepts up to 128 small (<=2048-byte) strictly typed JSONL local-stdin commands: `{"op":"revoke","grant_id":"apg_..."}`. Only `Revoke` is accepted; unknown fields, forged owner/context, oversized frames or unknown grants are denied, with sanitized confirmation on host **stderr**. The command is not exposed on QUIC, to a browser, to the model or to an external unauthenticated RPC; the current Session owner+writer epoch still governs each immutable revocation. This does **not** replace future local native-owner IPC/UX convergence.
5. **No automatic replay:** `actor_enqueue` uses the existing encrypted Pending Input queue and exact original sender source-sequence/request-ID collision ledger; no model call occurs at enqueue. `Step` first claims the item durably and confirms the original 9A Accepted fact, then invokes the original journaled Agent once. SIGKILL, client timeout, QUIC disconnect, typed Control, grant revocation, lease expiry or writer failover during provider dispatch can leave original Input `Dispatching/Unknown`, queue `Claimed/Accepted` and/or original model journal hazard; the owning Agent does not attempt an automatic second call. A successful `Applied` Control means **only the Runtime action was accepted**, not that an already-billed provider/tool effect was canceled or rolled back.
6. **Bounded concurrency and privacy:** Maximum 128 distinct requests per signed lease, 8 concurrent streams, 192 KiB request frame, 640 KiB output frame, 5–300s MachineLink lease; bounded query lists of at most 128 per 9C1. Client and server independently check the capability. The *one* Agent `tokio::sync::Mutex` allows at most one paid/model Turn; metadata/Control can run concurrently without creating an Agent. Redacted `public_operation` projections exclude ciphertext references, raw payload digest and process incarnation. `NoticeRead` is deliberately a separately granted private Accepted-observation operation, distinct from ordinary metadata queries. No generic remote `Bash`/Process/MCP grants are introduced.
7. **Scope limitation:** AwNet confirms **paired machine/Node** identity and a specific owner's Session grant; it does **NOT** establish a separate authenticated remote *human* user/OIDC/browser principal, nor that the paired machine's user is authorized for an unrelated Session. Explicit owner grant is required per Session/branch/site and expires or is revoked. The new service is opt-in, **Linux-only** AwNet QUIC, no default background daemon. Actual production Internet/network adversarial testing and real paid-provider billing are not certified by localhost tests.

## 3. CLI contract, with canonical flags

The local owner first creates/selects a saved SQLite Session with tools OFF, and separately pairs the machines using ordinary `aw net pair` as already supported. Between owner-server runs, the **owner** explicitly issues and, when appropriate, revokes scoped grants:

```sh
aw net actor-peer-grant SESSION_ID BRANCH_ID PEER_NODE_ID \
  --state-dir /private/aw-state --net-site local \
  --net-permission query --net-permission enqueue --net-permission step \
  --net-permission control --net-ttl 60 --output-json

aw rpc --agent-actor-peer PEER_NODE_ID \
  --agent-actor-room ROOM --agent-actor-rendezvous HOST:PORT \
  --agent-actor-grant actor-query --agent-actor-grant actor-enqueue \
  --agent-actor-grant actor-step --agent-actor-grant actor-control \
  --agent-actor-lease 60 --agent-actor-listen 127.0.0.1:0 \
  --session-id SESSION_ID --state-dir /private/aw-state \
  -C /same/working/root --provider-profile PROFILE --model-id MODEL \
  --tools-mode off
```

The peer (already paired, using **its own** private state directory) performs one strictly typed operation under the signed MachineLink lease:

```sh
aw net actor-request OWNER_NODE_ID SESSION_ID BRANCH_ID \
  --net-request-file request.json --net-room ROOM \
  --net-rendezvous HOST:PORT --state-dir /private/peer-state \
  --net-listen 127.0.0.1:0 --net-lease 20 --output-json
```

Examples of `request.json` are `{"op":"query","operation":{"op":"list_queue"}}`, `{"op":"enqueue","request_id":"unique","message_id":1,"text":"data only","priority":0,"target_turn":null}` and `{"op":"step"}`. For a reviewed exact current-Turn cancellation under the *same* signed connection, `aw net actor-request` optionally accepts `--net-control-file control.json` only for `Step`; this carries bounded `{"delay_ms":200,"control":{"op":"control","request_id":"unique_cancel","message_id":3,"action":"cancel_turn"}}`. Actual source-sequence values must be larger than all prior original Input/Control/Queue message IDs; these numbers are examples, not universal initial values. An existing owner server can instead receive the local stdin revocation command described above, then prevents further peer work immediately (Step checks on its next bounded 150ms owner-policy tick). No client is allowed to resend an uncertain attempted Step automatically.
