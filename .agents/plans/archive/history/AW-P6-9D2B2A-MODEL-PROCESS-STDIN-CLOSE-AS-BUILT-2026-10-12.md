## 1. Exact capability and consent design

- **One original model-visible Write action:** `process_close_stdin` takes exactly `{"op":"close_stdin","handle":"host_registered_opaque"}`. There are no other model operations, signal names, OS PID, program path, command args, stdin bytes, terminal, target Agent key, Tool permission fields, caller-selected Session/branch/site, source epoch or Process root. The opaque handle is printable ASCII identifier 1–64 bytes. The original ToolSpec declares **`ToolEffect::Write`**, never disguised as Read, and performs strict semantic validation independently of the provider's JSON-schema adherence. Any extra field, abnormal path/control symbol or action fails before intent. It **cannot** kill/terminate/resize/pty/suspend/signal/spawn a Process, deliver executable strings, inspect PID/stdout/stderr/environment, switch provider or paid Agent, open a microphone, or approve a guardian review.
- **Explicit current trusted host opt-in, default OFF:** `aw::model_process_control::install_close_stdin(&Service,&mut Agent,ProcessRegistry)` requires the **same** existing journaled Agent and generation-valid `actor_owner::Service`. Before registering anything in the original Agent, the live Actor Envelope MUST already have exact **`Host/trusted-host/epoch1/Write`** permission under the *new independent tool name* `process_close_stdin`; D1 `process` Read, prior `queue_enqueue/queue_update/queue_delete` Write, a remote peer, extension/MCP/project text, or a model-supplied name cannot grant it. The host installs via original `Agent::register_host_tool` / `ToolPolicy::permit_source`, preserving the existing source/site/effect/provider-account/payer and current cancellation checks at advertisement, tool invocation, execution and disclosure. This installation does **not** happen by default in CLI/R12/TUI/web/MachineLink, and it does not allocate a second Agent or scheduler.
- **Process custody is held by the ORIGINAL host:** Reuse `aw::model_management::ProcessRegistry`, already bounded to 16 opaque handles with exact current original Session/branch/site/principal/writer-epoch custody. The trusted host calls `register_owned` **only after independently authorizing and journaling the original Process spawn** with its existing ToolPolicy/effect. The registry stores an `Arc<tokio::sync::Mutex<PipeProcess>>` to that **already spawned** `aw-tools::process::PipeProcess`, not a PID or command. The new host-side `pub(crate) resolve` remains inaccessible as a general external model API, and the model cannot register/discover an OS Process. `PipeProcess::stdin_open()` is a trivial inert Boolean borrow from the original stdin state, not an effect receipt or external liveness claim. If Process stdin is already closed or busy, deny **before** minting a new durable intent. Only the trusted host can explicitly register/unregister resources; model cannot set that owner. The SDK cannot independently attest that an arbitrary trusted host obeyed its required initial Process spawn journal—this remains an original host provenance obligation, not solved by a pointer registry.
- **Current exact original journaled Turn:** `Service::prepare_model_process_close(&ToolContext,handle)` repeats D1's rigorous binding of the current actual owning `PrincipalId`, SQLite Session+branch and WriterEpochFence, live current Runtime Actor generation+Envelope and **currently active** `ActorMessage` claim, original immutable SQLite **`actor.input Dispatching`** admission matching the exact positive `ToolContext.turn_id`, original provider/credential/payer selection, execution site and uncancelled status. Separately verifies the new exact Host/Write `process_close_stdin` source grant. The model never supplies these objects or selects a different Agent, Process PID, target Turn or speaker/microphone. The host then mints one deterministic **`mp_` SHA256 ID per original Session+branch+originating Turn**, domain-separated from queue's D2A/D2B1 `mq_`/`md_` IDs. This forbids a second Process-control effect in the same originating Turn even if the model proposes multiple ToolCall IDs or different Process handles.
- **Immutable original SQLite v33 `actor.model.process` facts:** New derived `aw-store::model_process` service appends **existing** `audit` and `security_audit_events` records, no table/new schema. Typed `ModelProcessAction::CloseStdin` and `ModelProcessState::{Prepared,Applied,Rejected,Unknown,Inspected}` facts are bounded to 4096 per Session. `model_process_prepare` enters an original SQLite `BEGIN IMMEDIATE`, verifies current owner, live writer and branch, exact original `runs.status='running'` parent Turn matching writer epoch, original immutable `actor.input Dispatching` source/target/sender/Turn ID, and checks that **no prior `actor.model.process` intent for that original Turn** ever exists, even if it was already inspected. Commits **Prepared before any Process I/O**. This is a durable original-owner intent, **NOT** evidence that the underlying Process stdin was closed or any paid external work settled.
- **Original Process close and same-incarnation terminal receipt:** Inside the existing `PipeProcess` mutex the Tool validates stdin is open, commits Prepared, rechecks original owner/Turn, then drops exactly that Process stdin using the original `PipeProcess::close_stdin()` method. It calls `Service::finish_model_process_close`, which rechecks the same original host/WriterEpoch/ToolContext/Write grant and appends `Applied` only through `SessionStore::model_process_transition` when the fact is still exactly Prepared **and** the SAME pinned original owner-process ID and store generation that prepared it are alive. Applied means **only original stdin ownership was dropped**; it is *not* a child-exit receipt, provider acceptance, stdout completion or OS signal/termination guarantee. No PIDs, commands, environment or Process output bytes appear in the model ToolOutput or immutable audit. The original Agent still journals ToolStarted/ToolFinished and exact ToolStatus under the existing TurnMachine/ToolPolicy.
- **Crash, uncertainty and idempotency are fail-closed:** If the process crashes or source/Actor/writer/Turn authority is revoked after Prepared but before/after stdin close, the original immutable **Prepared/Unknown** fact remains, and no new write with the same originating Turn can proceed. A restarted owner process—even with an unchanged writer epoch—**cannot fabricate `Applied` or repeat the close**; it may only call host-side `model_process_inspect` to append a bounded printable Inspected note. Inspected does **not** clear the original Agent payment/Write Tool hazard. Two same-Turn Process-close proposals cannot create two OS side effects; at most one closes stdin, while the original Agent may correctly mark a conflicting Write batch Unknown/inspection-required, not a fabricated successful paid completion or automatic replay. Original `PipeProcess` remains the only resource lifecycle owner and cleans up its descendants according to the preexisting Process/PTY contract.
