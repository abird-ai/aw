## Changes and strict authorization semantics

1. `crates/aw-agent-core/src/journal.rs` defines **one** small immutable `ToolSourceEvidence {kind,id,epoch}` that is derived from the already registered `ToolSource`, with exact known `host|mcp|extension` kinds, original Source validation, bounded ID and strictly positive epoch. `JournalEntry::ToolStarted` adds **one optional `source` field**. It is recorded on the **same original started-effect intent**, NOT in another journal or audit. `None` deserializes old private JSON/JSONL entries and is omitted when reserialized; newer entries with provenance serialize the exact original source. Evidence is NOT a bearer token, permission or independent attestation of a hostile same-UID host. `ToolRecord` itself (presentation/RPC data) is unchanged. Public Rust code constructing/matching the `JournalEntry::ToolStarted` variant must account for the additive `source` field; this is a source-level SDK shape change, not an E5 C ABI change or a new JSONL file format version.
2. `crates/aw-agent-core/src/agent.rs`: the **original** ToolRegistry supplies `ToolSource` for EVERY wave or singleton original `ToolStarted`, including Host/MCP/Extension. Its exact source is copied before effect dispatch into the existing immutable Journal entry. A missing registry source is denied, not inferred from tool name or external hints. All previous ToolPolicy/Envelope live grant checks, current Session/Actor/generation/site, provider/payer selection, ordered intent-before-effect, factual original ToolFinished, post-effect grant revocation and no-replay rules remain unchanged. No source is accepted from provider JSON, Hook text or the model.
3. `crates/aw-store/src/journal.rs` and `crates/aw-store-jsonl/src/lib.rs`: both original durable journal `ToolStarted` append paths validate every PRESENT `ToolSourceEvidence` and reject malformed kinds/identities/epochs. For a host-approved `ToolRevised` argument transformation, a present started-effect source MUST match the original immutable revision's exact `source_id`, `source_kind`, `source_epoch` and declared effect; a contradictory source cannot launder a revised Tool into another grant. Missing legacy evidence remains readable/processable under the historical general Tool receipt format; it is not newly promoted into a verified first-party management grant.
4. `crates/aw-store/src/actor_queue.rs`: AW-P6-10D `original_model_enqueue_receipt`, while checking the already completed and attached original Run, exact original Assistant proposal, input, old `ToolStarted`/`ToolFinished` and initial encrypted Pending hash inside the same `BEGIN IMMEDIATE` model-disposition transaction, now additionally requires **`ToolStarted.source == Some(Host/trusted-host/epoch1)`**. Missing legacy, different SourceKind, changed original source ID or source epoch makes this **read-only historical evidence, NOT model-owned queue mutation authority**. The original pending queue item stays unchanged. No additional provider call, SQL source mirror, stable ID migration or loop is created. A legitimate earlier original `queue_enqueue` Tool/receipt continues to work, including after an authorized host-only Pending encrypted-text/priority edit.
5. Other owned first-party callsites in `src/minimal_sessions.rs`, `src/subagents.rs`, actual SQLite/JSONL fixtures and `crates/aw-agent-core/tests/parallel_read_waves.rs` account for this ONE optional field. Generic historical simulated fixture intents set `None`, rather than inventing unverified Host provenance; real original Agent intent events now set the actual registered source. All changes remain in the standard hosted layer; the original portable no_std kernel is unmodified.
