## 0. What we are building, what is already present

**Product objective:** make aw's runtime explainable in four primitives and two hook verbs, without giving up its existing durable Session/Domain/Workspace/Machine/Fleet, native/Web/RPC surfaces, no_std embedded host, C ABI, or exact-security architecture. Reduce the maintenance burden by consolidating separate control/hook/policy/child/process lifecycles as **derived services**, not adding a parallel engine.

### 0.2 Nonnegotiable product invariants

- ONE Agent / model loop / tool admission / ToolPolicy / TurnMachine / Journal semantic path. **No branch by full/minimal/embedded/CLI/UI creating a second Agent.**
- Tool grants OFF by default. Host/extension/MCP/model metadata cannot grant itself access. Exact source kind/id/epoch, actor, site and effect; recheck after awaits.
- Provider intent/receipt, paid results, and external effect intent-before-effect and factual receipt-before-disclosure. Unknown work is never replayed automatically, and cancellation never claims rollback.
- Actor/Session/principal/Domain/workspace/host account and payer are distinct. Host grants do not travel with imported text, shared Sessions, device links or browser views.
- Child Session budgets and writer fences cannot widen through delegation. Only explicit parent publisher moves child results into parent.
- One model-directed parallel Read/Bash wave design already exists; do not invent another scheduler and never parallelize mutating/Unknown effects implicitly.
- All new persistent operations respect SQLite v33 and current JSONL limitations; no compatibility migrations or sidecar durable authority store.
- Source v0.15.0, Phase68 historical tag, SQLite v33, pinned Rust 1.98.1; **do not** change release version/tag/migrations/publication without separately explicit approval.
- E6 PARKED; indexing/FS watchers Phase64 and LSP Phase65 skipped; no Phase69. R13 production/native certification is deferred and separate; do not revive external comparisons.
- Bare aw/help/list/show/inspect starts no MCP server, extension process, watcher, background daemon, voice helper, model call, network discovery or unapproved tool.

## 1. Faithful core contract and the essential deviations

~~~text
                 FOUR PRIMITIVES
Runtime = clock, bounded admission, continuations, wakeups, ownership
Actor   = Agent | Process; lineage, state, I/O, generation-fenced identity
Message = CONTROL | INPUT | NOTIFY | HOOK; ordered addressed communication
Envelope= exact host authority + budget + scoped resource constraints

                 TWO HOOK VERBS
Next(Some(message)) / Next(None)        Defer(continuation)

          ALL OTHER CAPABILITIES ARE SERVICES
queue, cancellation, process, child Sessions, tools, hooks, policy/approval,
deciders, planner/guardian/router, journal, prompt, settings, status, media,
MCP, UI, CLI/RPC, persistence — composed over primitives, not new roots.
~~~

The existing `TurnMachine` is a **pure deterministic state machine used by Agent**, not a fifth actor-system primitive. ToolPolicy is a service enforcing the Envelope; journal is a **mandatory effect service** and may not be turned off through optional hooks; providers are host I/O adapters. “Four primitives” is a concise semantic architecture, **not** a directive to combine unrelated Rust crates physically.

## 8. AW-P6-5 — one mailbox, queue, steering and cancellation

**Deliverables:**
- One `MessageClass::Input` queue per Agent: add/list/update/delete/reorder/start/pause/resume/clear as one service over Actor inbox; `Control` cancel/freeze/resume/resize/input/process/settle as kinds, not private buses.
- Canonical Turn/Step glossary; Step includes entire tool batch. Input `target_turn=Auto` or exact positive Turn. Priority proposed -20…19 with negative urgent and zero boundary. Reject out-of-range, stale exact Turn and caller/client duplicates deterministically.
- Controller authority: user and parent can steer their child; children only notify upward. Busy/nonsteerable reasons are typed (`compact`, `review`, `effect_intent`, `effect_running`, `effect_receipt`, `unknown`); no silently moving a stale targeted message to another Turn.
- Safe points: pre-model request admission, post-model complete response, after factual tool batch receipts, before next model dispatch and turn end. Urgent interrupt during paid attempt records paid/unknown; no speculative redispatch. Urgent interrupt of mutating process is cancellation request **not proven effect reversal**.
- Lifecycle and approval messages reserve capacity or yield backpressure; progress coalesces with drop count. No queue entry can mutate provider/account/tool grants or skip journal.
- Cancel exactly once, scoped Turn/Actor/Subtree/Runtime; process kind maps to actor cancellation only; Actor cancel cascades depth-first, Turn cancel preserves Actor and queued future input. Freeze never drops queue.

**Tests:** deterministic mixed priority/phase/sequence, auto vs explicit future, active vs idle, queue pause, overflow/reorder, simultaneous canceled/terminal, repeated/malformed client IDs, nonsteerable, restart pending queue revalidation, parent-child notifications, source revocation and writer-epoch change mid-wait, termination before/after intent, no double billing/retry.

**Acceptance:** existing `Agent::prompt` uses this mailbox without replacing its loop; a waiting child/approval cannot deadlock controller; no duplicate model or tool effect from steering.

## 14. Critical cross-cutting design choices before each dependency

### 14.1 Actor identity/generation and remote site

Choose an ActorKey whose generation fences slot reuse; hosted `ActorBinding` must contain actual principal/Session/execution-site/writer-epoch checks. Do not use raw PID, `session_id` as authorization, dynamic MCP source-provided actor labels or `client_id` alone as trusted identity. Site changes require a new explicitly admitted ActorBinding and new effect provenance, not in-place retarget.

### 14.2 Process resource ownership and freeze

Reuse one PTY abstraction, but do not make an interactive terminal tab into a Bash tool by implication. A `tty` process is just a process Actor whose output has UI metadata. Per-Actor output readers track separate cursors or a clear consume-vs-tail API; a late attach must not steal bytes from the model's process result. Freeze agents cooperatively; truly freeze an OS group only with verifiable platform support. Cancel frozen process = resume before graceful TERM then force. Optional CRIU checkpoint across shutdown deferred: does not solve durable paid/host external effects.

### 14.3 Journal and runtime durability

For every accepted effect-bearing message:
`authentication → admission/Envelope → hook/gate → exact authority check → durable intent (await) → authority recheck → effect → factual receipt (await) → safe output/next model`.
A message ACK, event, model-readable result or optional hook callback is never the durable source. A turn/child/Session may settle only with correct receipt state. Memory-only openly lacks crash recovery. No DB v34 schema or detached actor ownership without separate approval and proof.

### 14.4 Model stream steering

If a provider request has started, cancelling its HTTP stream may still incur usage; never automatically repeat it or mark cost zero. Urgent steer may be accepted as queued intent, but it cannot skip pending journal receipt, mutate provider signature or allow an already-started process to continue invisibly. Current first-party `BeforeDispatch` attestation-only retry semantics remain. Explicit user retry starts a **new** attempt with a new ID and current review of unknown results.

### 14.5 Budget, fairness and bounded resources

Carry forward current `max_model_rounds` (up to 32), `max_tool_calls` (up to 128), source-order and bounded Read/Bash wave ceilings, total 1MiB context/trace; do not introduce a second quota. Proposed new Actor cap 64, mailbox cap 64, pending queue cap 32, message text cap 64KiB, tail 64KiB, one drain up to 64, hook recursion cap 8 and default cancel grace 3s **are candidate host defaults from agentc**, not approved runtime limits until benchmarked and proven against existing aw tests. All caps must be configurable only within host-owned hard ceilings. Critical lifecycle events cannot be dropped on overflow, and a full queue rejects admission rather than silently evicting accepted user input.

### 14.6 Approval cache/policy revalidation

Persist scope only as an authenticated host audit/grant transaction; no permanent project-rule exception created from reviewer output. Current provider credentials, account grants, tool source epochs and roots are evaluated at actual effect time. A rejected/sandbox-unavailable operation can be explained to the model with correlated tool error; it cannot force alternative provider or machine without approved route.

### 14.7 Strict hook privacy/authority

Typed stage projections expose only allowed fields. Provider-private signed reasoning, credentials, tokens, raw prompt sources outside current disclosure, service account references and full tool wire cannot be copied to arbitrary output or extension observers. `NO_HOOKS` is allowed only for **optional** hooks, never journal, policy, grant, approval, privacy or context-output checks.

### 14.8 Source code and Rust API complexity

Keep the pure kernel small, favor enums/borrows/newtypes and explicit constructors; prevent dynamic dispatch proliferating in core. Host uses traits/adapters where hardware, store and provider boundaries genuinely differ. Avoid a generic Actor "do anything" op in the **in-process** Rust API; op-based text JSON is appropriate only at validated RPC/wire boundaries. Constrained typed enums are easier to maintain/fuzz. Avoid fake abstraction layers duplicating existing `AgentBuilder` or `TurnJournal`.
