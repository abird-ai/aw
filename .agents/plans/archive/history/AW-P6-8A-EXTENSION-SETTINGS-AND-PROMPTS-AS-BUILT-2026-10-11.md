## 1. Architectural commitments

- Exactly **Runtime, Actor, Message, Envelope**, and only Hook verbs **Next, Defer**. One existing Agent / ToolPolicy / TurnMachine / TurnJournal, same encrypted SQLite v33 and JSONL v1 durability, no hidden executor/process, no new provider/account/tool grants, no DB migration, new daemon, version release, Phase69/E6, skipped Phases64/65, push/tag or publication. The existing `aw-ui-extension` protocol and original built-in status/performance extensions remain the owning UI presentation layer, not a source of trusted OS/LLM tool authority.
- **Typed `add_setting`** is the existing `aw_ui_extension::Registry`'s *manifest-gathered* `aw_ui_extension::settings::SettingsRegistry` (also independently constructible). Each extension manifest may declare up to 32 bounded settings under its **own** verified manifest extension ID; no group object, foreign-namespace spoofing, project registration or runtime-added grants. One canonical registry validates types **Boolean / Integer {min,max} / Text {max_bytes} / Select {choices} / Secret {max_bytes}**, exact defaults and printable/bounded values, descriptions, identities, duplicates, 64 extensions and at most 256 definitions. `SettingsRegistry::{add_setting,new,definition,definitions,validate_user_value,resolve}` are pure trusted-host Rust APIs; `aw::extension_settings::{set,reset,list,resolve}` binds them to real user config.
- **User persistence and true CAS:** optional sparse `[extension_settings]` data is appended to the existing `FileConfig` (non-secret values only, no new version). Config `parse()` structurally bounds 64 extension namespaces, 32 keys per, 256 total, exact `{type,value}` Boolean/Integer/Text JSON and rejects raw/unknown/malformed/`secret` values, terminal controls, oversized text. The host validates every value against the currently registered manifest before it becomes active. The existing `config::mutate` creates/publishes atomic private TOML while holding the real advisory metadata lock; `set`/`reset` compare the **exact prior key** (`expected` value or `None`) and fail closed on stale writes. `config::save_changes` now merges changed keys **within the same extension group**, preserving independently modified status/theme/profile/skills/other extension settings. A reset removes only that persisted key, then returns its manifest default; it never persists defaults implicitly.
- **Precedence and exact project trust:** `CLI > verified project > user > default`. CLI setting overlays are **ephemeral, not persisted**. Project settings require an explicitly selected project root/cwd, existing no-follow descriptor-relative `Catalog::scan`, fresh complete approved hashes verified against the latest user configuration on **every** resolve, and one ordinary `.agents/settings/<extension>.<name>.json` file with a strictly typed `{type,value}`. The file is bounded to 4KiB and is inert data, not a remote extension, admin command, model tool or registered definition. Any unapproved/changed/revoked project hash causes a hard denial even when a CLI value could mask it; the user can still resolve without selecting the project. No automatic trust for random repository-local files or symlinks. Existing project trust command pins all approved sources; no separate shadow trust DB.
- **Secret segregation and honest OPEN:** `SettingKind::Secret` may be declared **without a default**, but secret SET/RESET/READ through ordinary TOML/JSON/project/CLI and public list are deliberately refused/redacted. There is **no implemented encrypted vault secret-setting backend** in 8A; an authenticated owner/SecretStore write/read lifecycle and redacted dedicated API require the separately reviewed 8B wave. A raw config string cannot masquerade as `Secret` by naming conventions or extension text. No plaintext secret values are persisted as part of 8A.
- **`add_prompt` typed composition:** New `aw_ui_extension::prompt::{Anchor,Placement,Content,PromptContribution,PromptRegistry,Document}` supports anchors `Preamble,Tools,Rules,Environment,All`, placements `Before,After,Replace`, deterministic `(priority,extension,id)` ordering, at most 64 registered contributions, 8KiB each, 64KiB composite, single Replace per anchor, duplicate/oversize/control-character hard failures. `Content::Host {text}` is trusted **only when registered directly by the owning Rust host**; source data cannot mint a grant. `Content::Project{name,sha256}` is restricted to `Before/After` of `Preamble/Environment`, never Rules/Tools/All/Replace. It is read ONLY from the freshly scanned, explicitly approved `.agents/prompts/<name>.md` project template with exact SHA-256; the content is presented as visually quoted **reference data**, not promoted to policy/provider/ToolPolicy or developer instructions. Project text changes, trust revocation or missing pinned source DENY rather than silently use stale bytes. Tool anchor strings are documentary; actual tool advertisements still come from the original granted ToolPolicy.
- **Original Agent factory integration:** `aw::extension_prompts::configured_agent_builder` builds the **same existing `aw::configured_agent_builder`** from an explicitly composed and validated `Settings.system_prompt`, before Agent creation. It does not mutate an already journaled Session/Agent, trigger a provider call, register a Tool, expose API credentials, change provider/account selection or install a background prompt service. This is opt-in trusted Rust host API; default CLI/web/TUI stays functionally unchanged, and untrusted external model/project content never implicitly registers prompt contributions.
