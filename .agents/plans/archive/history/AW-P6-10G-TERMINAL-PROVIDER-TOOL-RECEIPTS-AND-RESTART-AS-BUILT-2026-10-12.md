## 2. Two confirmed original SQLite terminal-receipt accounting bugs — reproduced BEFORE fix

**A — unknown paid provider attempt silently settled:** Original `crates/aw-store/src/journal.rs::append_sync` accepts original `InvocationFinished` with `meta=None` (failed or cancelled after an attempt that may have reached a provider) and marks the immutable `invocation_receipts.state='unknown'`. However its aggregate `llm_attempts.dispatch_state` update previously counted ONLY `state='started'`; the now-terminal `unknown` was ignored and `dispatch_state` silently became `provider_settled`. The final `persist_finish_in` repeated this error, treating absence of `started` as absence of unknown. Durable `DurableOperation.unknown_attempts` returned zero, recovery hints disappeared and the charge was presented as settled even though provider usage and dispatch were uncertain. This is a policy and billing observability bug, not evidence of an actual double-charge or default automatic replay.

**Negative-first native reproduction:** `aw_p6_10g_unknown_invocation_terminal_receipt_stays_unknown_after_run_finish` creates a real original SQLite Journal `InvocationStarted` and factual `InvocationFinished { outcome:'failed_or_cancelled', meta:None }`, then finishes the original Turn. The new explicit assertion on `RecoveryHint.actions.provider_dispatch_unknown` **FAILED before code change**, proving the bug; the Store had falsely closed the paid attempt. After fix it **PASSES** and also rejects any second original provider `InvocationStarted` in the same Turn after unknown outcome. Exactly one original attempt remains.

**B — proven never-dispatched request falsely treated as an unknown bill:** A safe bounded original `Agent` provider adapter returns `Error::BeforeDispatch` **before any request bytes are dispatched**. Its actual `InvocationFinished` has `outcome='not_dispatched'`, `meta=None`, unlike `failed_or_cancelled` with uncertain vendor billing. A naive all-unknown-terminal fix would label this proven safe negative outcome as possibly billable and interfere with the original explicitly opted-in pre-dispatch retry. `aw_p6_10g_proven_before_dispatch_original_agent_retry_is_not_unknown_billing` runs the genuine original Agent/Provider/TurnJournal against live SQLite: first actual adapter call returns `BeforeDispatch`, second sends a real local fake-provider completion. The new no-phantom-unknown assertion **FAILED** before distinguishing proven non-dispatch, and **PASSES** after correction.

## 3. One bounded original-ledger fix — no schema/API/ABI migration

**Production change ONLY `crates/aw-store/src/journal.rs`.** Within the existing original `BEGIN IMMEDIATE` and same `invocation_receipts`/`llm_attempts` v33 schema:

1. `InvocationFinished` explicitly distinguishes `(meta:Some(_))` verified response or `(meta:None, outcome:'not_dispatched')` trusted original Adapter **known terminal no-dispatch** from ambiguous missing metadata. The existing v33 `invocation_receipts.state='received'` is used for *definitively closed, non-unknown* outcomes, including the negative proof, with **metadata_json=NULL** for proven non-dispatch. This is existing schema vocabulary, not a claim that a vendor returned tokens, generated billable usage, or that an untrusted provider's plain text is a capability. All other `meta=None` outcomes stay `state='unknown'`. The original trusted Host/Agent/adapter is the security boundary: a malicious same-UID Rust host able to forge its own durable Journal is not independently cryptographically attested by this state machine.
2. Aggregate `llm_attempts.dispatch_state` after any terminal event now checks **both `started` and `unknown`**. It can settle to `provider_settled` ONLY when none remain. If either remains, it records `unknown` rather than suppressing an ambiguous charge. The original `persist_finish_in` repeats that exact conservative started-or-unknown predicate and preserves original `llm_operations` interrupted state, inspection hints and already opted-in bounded retry policy. Nothing automatically resubmits a paid request.
3. A NEW `InvocationStarted` is denied if any prior original `invocation_receipts.state='unknown'` exists for the same original run. This fail-closed source check occurs **BEFORE** acquiring any new provider execution lease and before the started receipt is inserted. It does not deny sequential known previous response or trusted BeforeDispatch no-call, so the original Agent can still perform permitted next model rounds and safe retries. When a new allowed ordinal starts after a prior definitively closed one, `llm_attempts.dispatch_state` correctly returns to `provider_started` instead of temporarily remaining `provider_settled` while another provider call is in flight.
4. An existing original `ToolFinished` or `InvocationFinished` for an effect that began under an older WriterEpoch is still appendable as **factual terminal evidence** after an epoch transition, but only via original prior matching intent/identity; duplicates fail. New paid Provider/Tool *starts* still use AW-P6-10F's original WriterEpoch CAS; no new writer inherits the stale run. Final branch-result attachment still checks original WriterEpoch, and can preserve completed billing unattached rather than attach to a new owner branch. A factual receipt is NOT permission to run an effect or to replay uncertainty.
