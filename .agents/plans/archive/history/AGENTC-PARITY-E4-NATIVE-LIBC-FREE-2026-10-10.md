## The distinction E4 actually proves

Prior E3 already actually ran the SAME aw-agent-kernel TurnMachine through aw-embedded and independently owned host callbacks with a wasm32v1-none no-import image under Node. Prior R13 could NOT truthfully establish a native libc-free image: the ordinary std Linux CLI has a PT_INTERP + GLIBC, and only import-free WASM existed.

E4 now builds the real original independent embedded Agent fixture in examples/sdk-embedded/src/lib.rs, with its two genuine fake-model calls, one source-authorized fake tool, validated intent-before-effect/reconciled receipt, ten kernel events, and final answer. **No new Agent loop, provider adapter, tool dispatcher, or Session database exists.** The same existing aw-agent-kernel/aw-embedded no_std+alloc libraries are linked into a separate **native Linux x86-64 statically linked ELF** that has **NO libc, C runtime, dynamic loader, dynamic libraries, unresolved symbols or dynamic relocations**. The host truly executes this path and returns actual code 0xA80E0001 and ten engine events, not just a compiled library or hardcoded fake "success" banner.

The independent runtime is ONLY examples/sdk-embedded-native/host.rs. It is no_std + no_main. An architecture-specific assembly _start shim aligns the kernel-entry stack before calling Rust under System-V ABI. All unsafe code required for this concrete native host remains here, not in the reusable aw libraries (which continue to forbid unsafe code). Host supplies:
- 4MiB statically backed, 4096-aligned bump allocator, atomic nonoverlapping layout reservations, allocator owned by the final image only;
- explicit panic-abort policy (Linux syscall exit 127), and an unreachable precompiled core/alloc personality shim that exits with 126 rather than linking libunwind;
- correct independent compiler memory primitives memcpy, memmove (both overlap directions), memset, memcmp and optimized bcmp, using volatile writes/reads to avoid compiler recursively lowering their implementations into libc calls. A real stack-buffer self-test verifies those primitives before any provider/tool work;
- only raw Linux x86-64 write/exit syscalls for terminal proof and process termination. There is NO separate standard library, std::fs, Tokio, network stack, DNS/TLS, database, loader, libc/startup object or shell interpreter in the final image.

The native no_std example is compiled with rustc and an actual ld.lld linker using locked target-local Cargo build dependencies. There is no added public Cargo crate/allocator dependency or unsafe feature in the existing aw libraries. The x86_64-unknown-linux-gnu target triple is deliberately retained because this installed host lacks x86_64-unknown-none core/alloc and complete native rust-src. The final ELF is nonetheless libc/CRT-free by **binary structural proof AND real host execution**. The GNU-target name is a compiler target selection, NOT proof that libc is linked. Conversely, absence of PT_INTERP alone would be insufficient; the full audit checks program headers, dynamic table, relocations, undefined symbols, compiler memory symbols and actual running behavior.

## Explicit limits, safety and next work

**Native Linux libc-free with raw syscalls is not freestanding firmware.** Linux kernel process launch, virtual memory and write/exit syscalls are still required. True x86_64-unknown-none, thumbv7em-none-eabi or RISC-V bare metal needs a target core/alloc stdlib and rust-src/bootloader/panic/stack/board or qualified QEMU. This host has neither those target stdlibs nor full rust-src (only compiler sources); no bare-metal linkage/running was claimed. No dummy native bare metal artifact is substituted.

**E5 independent C ABI** is a separate future phase: versioned opaque handles, explicit pointer/length/alignment/lifetime, no unwind across FFI, caller allocator/callback custody, independent actual C process and binary layout tests. A Rust function named _start and compiler-owned memcpy symbols are NOT a shipped aw C SDK. **E6 board/firmware** and embedded real network/TLS/tool/clock/entropy ports are also separate and currently OPEN. Cross-platform release binaries and pinned 1.98.1 remain R13 global certification gaps. Do not link libc by using static musl and mislabel it libc-free. No release publishing, Git push, schema/version bump, numbered Phase69, or revival of intentionally skipped Phases64/65 LSP/indexing.

A manual read-only six-host native R13/R14 workflow gains a Linux x86-64 **E4 debug and release** execution step with per-host artifact receipts. It has NOT RUN and therefore certifies no additional platform. Other six native CI runners are not given an unsupported E4 "pass."
