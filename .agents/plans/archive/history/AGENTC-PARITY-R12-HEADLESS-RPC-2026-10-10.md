## Architecture — ONE existing Agent, not a competing RPC Agent

R12 adds a transport/projection adapter only. All inference and tool effects call the same aw-agent-core Agent through the same full/minimal Host, source/account/executor leases, exact grants/source epochs, hooks, journaling and portable turn state machine. No RPC or JSONL code grants tools, changes vendor accounts, creates a new provider loop, or executes a shell directly. Never auto-replay an uncertain external effect.

Shared std-only src/headless.rs implements one v1 JSONL Emitter, protocol Request and bounded stdin server/Driver. One-shot aw --output jsonl --print TEXT emits real typed AgentEvent stages and a final settled/error event; stdout is machine JSONL only. Full aw rpc --stdio uses existing ProviderCliArgs/ToolCliArgs/TargetCliArgs. JSONL-minimal uses the same ordinary root flags before its explicit rpc --stdio subcommand. Both invoke the existing host; no hidden TCP listener/daemon. Full uses a distinct internal rpc_stdio Clap argument ID so its visible --stdio does not collide with an MCP option.

Each output frame is JSON with v=1, monotonically increasing seq, type, id and data. The first RPC output is a versioned hello/capability advertisement before a provider request. Each effectful request emits accepted first, actual stream events including model deltas/tool started/finished/provider-attempt outcomes next, then settled with factual saved Turn/needs_reconciliation status. Acceptance is NOT completion; lost pipe or missing settled is UNKNOWN, never a safe retry. The user must inspect their exact persisted Session ID on a new connection before manual decisions, not assume --resume means the previous active Session.

Input resource policy: 192KiB max request line, 640KiB max output frame, 64KiB bounded event fragments split at UTF-8 boundaries, queue32, max1024 unique IDs per process, get_messages max12 recent public Turns (bounded prompt and answer text), and tool result projection max16KiB with explicit truncation marker. Reader drains oversized lines without unbounded allocation and rejects malformed JSON, bad version, unknown method params and duplicate request IDs before dispatch. No raw provider-private signed thoughts/headers/credentials or arbitrary tool arguments are serialized into public event projections.

## Methods, trust, cancellation, and limits

get_state, available_models (no implicit network discovery), get_messages (recent bounded public projections), prompt and prompt_template (R11 source-pinned named project only). Templates are explicit user content, expanded exactly once, never new system authority. set_model and set_effort work only within already-authorized stateless profile/allowed models; provider-bound durable Session changes are denied. new_session and open_session use existing owner-bound JSONL Session selection and journal restoration, with full root sibling unknown-effect check. compact is only available for current authorized R10 JSONL Session, never a hidden paid summary. SQLite retains its separate ContextFlow.

abort accepts an exact target_id: a bounded reader thread signals that active cooperative cancellation token while the main thread is in the one Agent loop. Reply reports cancel_requested accurately (true only when a matching active token was signalled). Already-dispatched provider/tool effects are not undone, and the status/Session journal still records unknown effects. Other state operations are serial; no background shadow execution.

Direct privileged RPC trusted_bash and extension_control are not enabled: a separate audited owner action would require its own durable intent/effect/grant policy. The model can still call already-granted Bash through the ordinary Agent tool path. The hello advertises these unsupported capabilities as false. No success-shaped placeholders.

## Independent SDK clients

examples/sdk-rpc-client is a real independent Rust workspace package aw-rpc-client-example with typed client, child-process demonstration and no dependency on aw-agent-core, store or provider internals. Its read/write protocol verifies monotonic frames and treats any EOF/pipe break after write as TransportUncertain, never auto-resends. A second standard-library-only Python client in the same directory provides an independent cross-language implementation. Both execute real separate child aw binaries against mock local SSE provider in the fixture. README documents full vs minimal flag placement, exact Session reconnect and privacy.

--diagnostics-protocol under Diagnostics & validation (off by default) logs only event type and encoded byte count to stderr; no raw JSON, user content, authorization/cookie headers, OAuth credentials, tool arguments or private provider continuation. Raw wire recording is deliberately unsupported and does not become available by toggling diagnostic output.
