### V3. Independent original v33 audit record with race-safe re-verification

PRIVATE `record_cold_activation_dry_run(archive, cold_state, challenge, device_key, detached_signature, exact_dry_run_id)` records an optional **immutable data-only** original `local_coordination_events.kind='store.cold_activation_dry_run_recorded'` receipt, with maximum 32 per restored generation, strictly bounded unique request IDs. It never stores actual device signature, credential, Queue body, ToolOutput or account bearer secrets. File/sync follows original private owner-only SQLite handling; no extra SQL table or ABI/API is introduced.

**Actually discovered/fixed during post-interruption review:** the first implementation performed full read-only signed/AEAD/risk validation BEFORE opening its original `BEGIN IMMEDIATE` audit transaction, so a trusted-local SQLite mutation in the gap could have made the subsequent event stale. V now re-executes the SAME signed consent, current original U grant/Ed25519/epoch, full source Q/R/S/T custody+effect-risk, and original writer eligibility **WITHIN the acquired `BEGIN IMMEDIATE` transaction**, and compares its complete private `ColdActivationDryRun` facts to the initial result. SQLite permits read-only inspection connections while the write reservation prevents another cooperating SQLite writer from changing original audit/Actor/identity metadata; a mismatch DENIES before recording. This is bounded two-pass validation for an internal operator-only audit, not a new runner. It also still rejects stale original Process/WriterEpoch/coordination/maintenance leases and duplicate request IDs inside that same transaction.

One PRIVATE fault-injection seam `record_cold_activation_dry_run_with_pretransaction(..., FnOnce(&Path))` exists solely for deterministic native tests. Normal original code passes `|_|Ok(())`; the seam is NOT an extensible runtime Hook, model/Tool/SDK API or permission mechanism. The native tests inject a new potentially effectful original Run and a device-key revocation at this exact pretransaction window. Both must fail and write **ZERO** dry-run audit entries. The review is still bound to the trusted-owner local filesystem/SQLite/OS, not adversarial arbitrary root/same-UID file replacement or real hardware crash durability. A copy made AFTER U issuance can duplicate local immutable U records; this implementation does not claim global signer uniqueness or use one new central ledger.
