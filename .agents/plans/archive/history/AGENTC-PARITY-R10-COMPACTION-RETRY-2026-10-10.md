## Architecture, ownership and safe defaults

R10 adds two *policies*, NOT parallel shadows of the existing Agent execution loop or storage:

1. **Bounded active-tail compaction** is a pure planning rule in aw-agent-core::compaction: Mode Off | Ask | Auto (DEFAULT Ask), threshold/recent-turn bounds, maximum summary bytes, optional actually known model-context window and a separate explicit user-paid-auto switch. A trigger is a suggestion, never implicit authority to spend. The immutable plan binds session ID, expected next turn, exact public evidence SHA-256, current active tail and prior checkpoint. Each cut keeps complete recent turns (including their tool call/result batch; never split), carries prior lossy summary with digest/source provenance, checks the complete snapshot before any provider attempt, and fails if evidence exceeds the 512KiB input bound. No raw provider-private thinking or restored credentials/tokens are sent to summarizer.
2. **One existing SummaryExecutor** remains responsible for the paid tool-free provider call and current account/model/executor lease; a SummaryJournal stores an immutable *paid intent* and outcome outside ordinary Turn history. A backend-owned CAS applies a successfully settled candidate. There is NO direct provider HTTP call in the compaction controller and no invisible regenerated paid summary on restart.
3. **Full SQLite** continues its existing prepared ContextFlow source plans, immutable evidence, summary generator and CAS application (no copied engine). **Full and JSONL-minimal modes** use one new shared aw::jsonl_compaction::compact helper and the same backend-neutral SessionCursor::compaction_journal/apply_compaction/compaction_ready seams. The normal store mode/capability still selects backend; JSONL never claims multiuser ContextFlow authority.
4. **JSONL active tail** uses three append-only record types: CompactionStarted (exact source/account/model paid intent), CompactionFinished (outcome/usage), ProjectionCompacted (source-head CAS checkpoint). They are appended + flushed + sync_all in the established same-UID single-owner journal. The raw file still retains all original TurnFinished entries, while the active HistoryState retains only recent complete attempts and a model-derived, clearly attributed, unverified summary, digest and compacted-through cursor. Existing Session/branch next turn IDs stay monotonic (no reset/reused IDs). Source revision and all recorded evidence are verified before accepting a checkpoint. A successful summary that settled but was not applied may be applied after restart WITHOUT another provider request. An uncertain paid attempt is blocked until user inspection and explicit acknowledgement, not replayed or silently treated as free. Duplicate request IDs never regenerate.
5. **JSONL replay scalability:** complete projection validation is performed ONCE after replaying all appended records. Previously repeated expensive full-history validation after every turn exacerbated quadratic JSONL replay overhead. The final returned history has the same validation; partial/uncommitted records remain fail-closed. Existing format version remains v1; older JSONL files with no new fields still decode. Active-tail compaction does not magically remove the finite 32MiB raw JSONL log limit; the full backend remains recommended for very long histories.
6. **Conservative RetryPolicy:** defaults to ZERO extra provider attempts. The only eligible auto case is Error::BeforeDispatch, which can ONLY be supplied by trusted Rust adapter attesting absolutely no vendor request bytes dispatched. Explicit --provider-pre-dispatch-retries allows 0–2 extra attempts, each with its own separate durable InvocationStarted/Finished ordinal and no prior tool effect, no stream fragment and same selected actor/account/model. Every retry counts toward max32 attempts and the existing overall request deadline; stream, HTTP, Timeout, Cancelled and generic Transport errors may already have been billed and NEVER silently retry. BeforeDispatch is an SDK-level affirmative contract, not proof from an arbitrary remote service. Provider adapter support is opt-in; built-in HTTP transports return normal ambiguity errors and do not currently assert BeforeDispatch.
7. **Config and UX:** CLI --context-compact-mode ask|off|auto (default ask), --context-keep-recent (default16, 1..64), --context-trigger-turns (default64, 2..256), --context-known-window-bytes (optional), --context-auto-spend (off), --context-compact-now (explicit one-shot). In minimal the interactive /compact triggers authorized summarization; full SQLite keeps its existing explicit Context command/ContextFlow and full JSONL supports --context-* plus one-shot compaction. Both use the same helper. Auto requires *both* known context budget and explicitly selected paid-auto consent; without either it only asks, never spends. Manual compact is an explicit paid summarization under current provider custody; original history remains available in the JSONL log.

## Explicit limits and follow-up

- JSONL finite raw log size (32MiB) is unchanged; compaction advances active MODEL projection, not physical log pruning or authority-bearing private state. SQLite remains the rich multiuser and materialized source engine.
- The R10 first slice uses a bounded active-turn count with optionally known context metadata; exact provider tokenizer awareness, independent per-session cost budgets, large-input chunking, multi-step summary dependency linking, and automatic SQLite ContextFlow compaction remain future enhancements. Do not assume unknown token/window/cost information.
- A strictly affirmative trusted no-dispatch adapter error is required for retries; a generic HTTP connection error, 429/503, Retry-After hint, dropped socket, cancel or partial stream is not proof of no paid dispatch. No automatic post-tool retry and no account/model failover.
- No live vendor provider, account/credential/authoritative OS sandbox audit, pinned Rust 1.98.1 runtime, native libc-free ELF, release reproducibility, or automatic billing verification is certified here.
- R11–R13 remain in roadmap, R14 complete CLI taxonomy and shared Clap Args migration is the user-requested tracked future phase; no historical numbered Phase69 or Git push.
