## 1. Selection, model, host, trust and denial decisions

1. **Explicit mode:** `aw rpc --agent-stdio --agent-actor-owner --session-id EXISTING` with the normal required same profile/model/root and private SQLite `--state-dir`. The sole new canonical long option is `--agent-actor-owner` (Clap internal `--actor-owner`; current R14 taxonomy derives the final canonical name). It is not the default. It is disallowed for `--state-memory-only`, JSONL/minimal/stateless, implicit `--session-resume`, missing Session ID, tool-enabled mode, MCP/extensions or subagents. The existing `aw rpc --agent-stdio` behavior without this flag stays ordinary first-party R12; **actor methods there continue to advertise false and respond `unsupported_method`** without inspecting raw ActorKey strings. This is an already trusted local OS-owned stdio process, not remote/user-token authentication, device pairing or a new network listener.
2. **Host mints all authority, not RPC fields:** the actual SessionStore’s current owner/principal, Local Workspace writer **epoch/local node**, already selected SQLite Session/branch and original journaled Agent are checked *before hello*. The Host creates an unpredictable fresh `RuntimeKey` ID+generation from OS randomness, uses existing `HostRuntime::bind_agent` with exact trusted SessionBinding/epoch and Actor `Running`, an Envelope at the already selected Agent execution site, only **read-only/no-network/no-process/no-terminal/no-media/zero exact grants**. `AgentSessionController::verify_current_binding` rechecks current live Actor generation/state, Envelope, trusted Session owner/writer epoch on **every transport operation**; the original Agent verifies its journal and already selected provider/ToolPolicy. The Envelope budget ceiling matches the preexisting Agent’s declared maximum, but `--tools-mode off` plus **empty grant list** forbids all Tool effects. No content from JSON can choose sender, actor generation, site, owner, credential, payer, grants, branch or writer epoch.
3. **One exact typed operation vocabulary:** new `aw-agent-core` `verify_current_binding()` and `aw::actor_owner::Service::{verify_rpc_agent,operate_bound,enqueue_bound_text}` reuse the original Store/Runtime. `ActorOperation::from_rpc_value` strictly checks exact fields **including unit enum variants** (Serde ignores extra fields on such variants otherwise); forbid raw `actor_key`, `writer_epoch`, `admin`, `grant`, `source`, unknown or extra operation fields. `operate_bound` filters queried Control/Queue/Notice to the **selected Session, branch and recipient site**, and refuses operating a terminal/retired Actor, stale epoch or foreign Session. Metadata-only lists return explicit Limit beyond **128** entries rather than silently truncate or exceed the R12 frame ceiling. Exact query-by-request-ID works even for old settled facts. A new future cursor pagination contract remains open.
4. **Transport methods:** `actor_query` accepts only typed `QueryInput, QueryControl, ListControls, QueryQueue, ListQueue, QueryNotice, ListNotices`, projecting reduced data only (no Input/Notice ciphertext, raw SHA256, private secret ref, process IDs, provider-private continuation or raw authoritative grant). `actor_op` allows only typed human/operator dispositions `InspectInput, InspectControl, DeleteQueue, InspectQueue, AckNotice, InspectNotice` with existing persisted note/revision rules. **No externally replayable Control**: serial stdio has no concurrently owned active Turn to prove an immediate current `CancelTurn`/Freeze; `ActorOperation::Control` is denied. No `trusted_bash`, MCP/extension control or OS Process effects, no approval forged by model text. `actor_notice_read` is explicitly owner-only **private** text retrieval of a previously Accepted observation; query/list endpoints never return that text and acknowledgment is independent `AckNotice` CAS.
5. **One journaled Input path:** `actor_enqueue` accepts only `request_id, message_id, text, optional priority, optional target_turn`. It mints **the same** ActorMessage `Kind::Input` with host-authenticated current ActorKey sender/destination/Turn (Auto or exact); it calls existing **9B2A** `Service::enqueue`, encrypted pending custody and immutable request/sequence collision checks. No inference/model call is performed on enqueue. `actor_step` explicitly claims only a current admissible pending message under SQLite/branch/recipient/writer CAS, independently verifies original 9A accepted facts, and runs the same original `Service::run_once` / `Agent` / ToolPolicy / TurnJournal; it never creates a second model runner. `actor_step` streams the normal R12 `AgentEvent` and factual `settled` or `unknown_or_rejected`; `actor_query` and `get_messages` remain data-only. `prompt`/`prompt_template`, live provider/model/effort rebinding, switching Sessions and compaction are denied while this owner is attached to prevent a shadow unfenced provider path; only non-owner ordinary R12 retains these features.
6. **No replay, no false receipt:** R12 `accepted` acknowledges reception of a bounded, validated *transport request*, not provider dispatch, durable enqueue, user observation or OS effect completion; successful `settled` follows actual Store/Journal facts. The original 9A/9B2 queue admission persists `Claimed` **before** volatile delivery and `Accepted` after original mailbox acknowledgement. A dropped/timed out/cancelled model future, SIGKILL, reader/socket EOF or failed frame write can leave immutable original Input `Dispatching/Unknown` and queue `Accepted/Claimed`; a new owner cannot replay either. Only untouched `Pending` with same writer epoch/Session/site can rebind to a new unpredictable Runtime generation. Independent notes/inspection do not erase hazards. RPC request IDs are per-connection limited (1024), original admission `request_id` + sender source sequence are durable and collision checked across Input/Queue/Control/Notify. No global exactly-once paid-service claim.
7. **Feature portability and privacy:** `durable` feature includes its already-existing optional `getrandom` dependency so new Runtime generation works even in its feature cut, no `Cargo.lock` change or new crate. Minimal/stateless agent remains no durable owner. R12 outer request <=192KiB, max 640KiB frame, 32 in-memory frames and fixed host audit/queue bounds, no new protocol version. Error/public outputs deliberately remove private hash/ref/payer/process markers. The only private payload intentionally disclosed is `actor_notice_read`, invoked by the current OS process/Session owner; no remote transport consent is inferred.

## 2. Actual behavior / invocation contract

Start an ordinary SQLite Session with `aw` using the intended local profile/model/working directory and tools disabled. Note the exact Session ID, then launch the already trusted **local** process:

```sh
aw rpc --agent-stdio --agent-actor-owner --session-id s_EXISTING \
  --state-dir /private/aw-state -C /same/working/directory \
  --provider-profile PROFILE --model-id MODEL --tools-mode off
```

After the versioned `hello` with `actor_query/actor_enqueue/actor_step` capabilities `true`, send the following distinct complete JSONL frames to this same process; the shown `message_id` must be **strictly greater than all historical original source + queue-claim sequence values**, not just another client’s most recent enqueue:

```json
{"v":1,"id":"frame1","method":"actor_enqueue","params":{"request_id":"new_unique_intent","message_id":1,"text":"Hello from the original Agent", "priority":0}}
{"v":1,"id":"frame2","method":"actor_query","params":{"operation":{"op":"query_queue","request_id":"new_unique_intent"}}}
{"v":1,"id":"frame3","method":"actor_step","params":{}}
```

The initial `message_id:1` is **an example for an empty Actor sender history only**; a current Session may have prior controls/claims and reject it. Inspect immutable queue facts on failure; do not automatically retry a request ID after lost transport. Public queue/notice views contain no private ciphertext ref, unkeyed digest or process ID. For exact `notice_private` retrieval use the dedicated `actor_notice_read` method only with a Notice proven `Accepted` and explicitly read-ack it via `actor_op` `ack_notice` with exact revision.
