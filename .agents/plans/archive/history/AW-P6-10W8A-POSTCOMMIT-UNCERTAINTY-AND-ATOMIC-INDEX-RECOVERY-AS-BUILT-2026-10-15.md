## 2. Native-reproduced correctness defect W8A-01 (HIGH)

**Before:** The original W8 `record_original_owner_effect_review_impl` did `tx.commit()?`, then `after_commit()?`, file synchronization and original full source/dual-quarantine re-verification with ordinary `?` errors. A fault **after** SQLite committed its immutable review receipt therefore escaped as `Error::Denied` or `Error::Io`, indistinguishable to generic callers from a definite pretransaction refusal/rollback. This was inconsistent with the required immutable-original-effect crash/no-retry contract.

**Native negative first:** Added `aw_p6_w8_postcommit_fault_is_explicitly_unknown_not_a_retryable_rollback`. It injects a deterministic error immediately AFTER actual SQLite commit and BEFORE explicit fsync, asserts the returned error is **Storage with 'outcome unknown; inspect'** and verifies the original immutable audit row exists, remains singular despite a new request ID and the original cold State cannot open. The test **FAILED on the old source**: it returned `Denied("synthetic postcommit sync failure")` despite one already-committed row.

**Fix:** After the first potentially irreversible `tx.commit()` attempt, every failed acknowledgement, postcommit callback, file/fsync/parent sync or original archive/AEAD/quarantine re-verification now maps to one explicit `Error::Storage` diagnostic:

`cold original owner review audit outcome unknown after commit; inspect original immutable receipt; never automatically retry or execute`

This is not a claim that `tx.commit()` actually persisted when it reported failure, nor a claim any original provider/Tool effect completed. It is a deliberately conservative **unknown-audit-outcome** signal, requiring examination of the original immutable v33 review event. Pretransaction denials still retain their original denied/conflict semantics and make **no** audit entry. W8 original review booleans remain `runnable=false`, `original_effect_settled=false`, `fresh_authority_granted=false`, `automatic_replay_allowed=false`.

**Additional native tests:** `aw_p6_w8_precommit_denial_retains_original_error_and_no_audit_record` verifies genuine precommit denial and later explicit fresh review request under unchanged original State; `aw_p6_w8_postcommit_quarantine_corruption_reports_unknown_after_original_audit` removes the filesystem cold quarantine marker after real SQLite COMMIT and verifies that postcommit custody failure yields explicit unknown, the immutable audit row is preserved and the independent original SQLite quarantine still prevents normal `SessionStore::open`. Existing native child-process exits before and after commit, two concurrent owner requests and two offline clones stay unchanged.

## 3. Git commit-helper durability defect W8A-02 (HIGH), fixed

**Before:** The original newly added the removed aw_signed_atomic_commit helper used a full expected-parent candidate tree, reviewed-path allowlist and a private index, then under `.git/index.lock` executed the signed `git update-ref HEAD <new> <expected>` compare-and-swap **before** replacing the shared Git index. If the filesystem `os.replace(index.lock, index)` failed after HEAD CAS succeeded, its unconditional `finally` removed the lock, discarding the **only prepared opaque staging snapshot** for the newly committed HEAD. This could leave a signed new HEAD alongside the old shared Git staging and no recoverable prepared index.

**Native negative first:** Extended the independent fully disposable fake Git repository test with a second reviewed commit and an OS-level `os.replace` failure injected strictly **after successful HEAD CAS**. The old helper raised the raw `OSError`, removed `.git/index.lock`, and did not signal the necessary manual recovery. No real repository index or UX-owned source was accessed.

**Fix:** The helper tracks `cas_advanced` separately from lock ownership. A failure before CAS cleans up the abandoned private lock. A failure after successful CAS while installing the index **PRESERVES `.git/index.lock`** holding the already-written and fsynced complete opaque index, including every unrelated staged entry, and raises an explicit `RECOVERY REQUIRED` exception. The user/agent must inspect the exact signed HEAD and preserved index under exclusive lock before supervised repair. A parent-directory fsync failure **after index replacement** similarly reports uncertain index durability, not categorical success. This is an honest failure-closed recovery protocol; ref CAS and filesystem index rename are not one kernel atomic transaction. The full candidate tree is still checked byte-exactly by reviewed-path allowlist, original author and ED25519 signature are verified, and no staging/ownership from `.agents/plans/ux/` is accessed.

**Native positive/negative tests:** In the temp Git repo, the post-CAS simulated rename failure left the signed second HEAD plus recoverable `.git/index.lock`; its contents still contained the two unrelated staged paths (including a synthetic *other agent* UX example). The test performed a separate explicit simulated manual repair, verified both staging entries still match original bytes, rechecked stale-parent CAS and path/UX refusal, and passed. No real Git signing key used in the test.

**Additional negative-first interruption test:** A third synthetic signed candidate succeeds in real `git update-ref HEAD` but a fault raises **before the helper sets Python's `cas_advanced=True` flag**. The old helper removed the only prepared index lock because it trusted that stale in-memory boolean; native test FAILED. W8A now records `cas_attempted=True` **before** invoking the ref-update subprocess and, in the finally block, re-reads actual HEAD. It removes an abandoned index lock only when ref CAS **definitely** did not advance; any ambiguous ref-read outcome or advanced ref keeps the fsynced opaque index lock for explicit recovery. The updated independent test PASSED and also verified preservation of an unrelated staged UX fixture. This closes the interrupted-subprocess/HEAD-return gap without broadening commit helper authority. A genuine unexpected power-loss or another process not honoring `.git/index.lock` remains outside automatic repair; fail closed and inspect. No real user UX files were accessed.
