## 2. New original operator-only inspection API, no new ledger or format

**Production changes:** one NEW private implementation module `crates/aw-store/src/secret_custody_inventory.rs` registered in `crates/aw-store/src/lib.rs`; one small `pub(crate)` read-only typed latest-Extension-fact helper in `crates/aw-store/src/extension_secret.rs`. Existing `LocalSecretStore`, original v33 Queue/Provider/OIDC/OAuth algorithms, encryption keys, credential creation/rotation/expiration rules, original Session/Actor runtime and original paid receipts are not modified. The only additive host Store API is `SessionStore::verify_active_secret_custody(&LocalMaintenanceLease) -> Result<ActiveSecretCustodyInventory>`. It exposes **counts only** (`queue`, `extension`, `provider`, `oidc`, `oauth_client`, `oauth_token`, `active_unique`, `unreferenced_items`); no raw `sec_` item IDs, plaintext, original body hashes, nonce, key, blob paths, ciphertext, provider metadata, executable Tool, JSONL/bundle serialization or remote RPC authorization is added.

**Original owner & maintenance proof:** Before reading any encrypted item, the method requires an actual persistent on-disk Store, exact original `purpose='backup'` lease token matching the currently held exclusive `Inner::vault_maintenance` OS lock (held via original `Arc<Inner>` across clones), current coordinated owner process ID/store generation, current SQLite `local_maintenance_lease` row with matching lease generation and expiry **in the SAME original Store**, and an unexpired original clock. A copied/stale or released token is denied, and a caller without the original live owner vault fence cannot enumerate custody. The read-only scan holds that original fence plus the original SQLite mutex for its full bounded duration, so cooperative original writers cannot mutate ciphertext or v33 original audit while inspection is active. No new SQL transaction, background process or separate credential grant is created. It uses existing v33 SELECTs and original authenticated `LocalSecretStore::get`, not a parallel decryption implementation or cryptographic signing scheme. No master key is minted on an empty never-used Store; a current active ciphertext obligation with a missing master/key/item fails closed.

### Current active-state classification from original, never from filename guesses

- **Actor Queue:** Read ONLY original immutable `audit.action='actor.queue'`, ordered by `seq`, latest actual `(session_id, request_id)` fact using the original strongly typed `ActorQueueFact` and exact matching Session ID. `Pending`, `Claimed` and `Accepted` remain encrypted custody obligations; `Deleted`, `Settled`, `Inspected` are not reactivated by any old fact. The original latest `payload_ref` and `payload_sha256` are required, both bounded in shape. A valid AEAD under the same reference is NOT enough if the decrypted Queue body differs from the original immutable digest. No effectful queued input is claimed or replayed.
- **Extension Secret:** Read ONLY original immutable `audit.action='extension.secret'`, project each bounded typed `SecretSettingFact` via one original extension-owned `pub(crate)` helper, keyed by exact Session/branch/site/extension/name, and use only the final `Active` `blob_ref`. `Removed` and superseded versions are not current obligations; missing active ref or forged Session ID fails closed. The helper is private crate-only and does not leak refs into model/web/QUIC/extension contexts.
- **Provider server secrets:** Use actual `provider_accounts` with `status='active', credential_custody='server_secret'` AND exact current `provider_secret_versions(provider_account_id,secret_version,secret_ref,status='active')`. A missing or superseded version fails inspection rather than treating the associated file as accepted. Revoked/unavailable historic versions are not active obligations.
- **OIDC provider secrets:** For actual active OIDC client-secret-auth providers, require matching `oidc_provider_secret_versions` active and identical current version/ref. `client_auth_method='none'` requires no secret. Prior rotated/revoked provider records do not grant a new live credential.
- **OAuth connector:** A client secret attached to a current `configured` or `active` OAuth connector requires exact active `oauth_connector_client_secret_versions`; its active/current token (including a conservative configured account retaining a token ref) requires exact active `oauth_connector_token_versions` for that selected version/ref. Revoked/unavailable accounts and superseded versions are not active. No token-body parsing, network renewal, provider API calls or billing occurs during the operator scan.

**Bounded read-only work:** Each immutable audit action may contribute at most **32,768 rows** to an operator inventory; each version-class query at most 32,768 rows; all unique CURRENT active ref obligations together at most 32,768; and the existing `secrets/items` directory at most 32,768 entries. Exceeding any limit fails closed with explicit operator review; no truncation or false success. Every private item filename must be a canonical `sec_<64 hex>.bin` or original `.secret-<16 hex>.tmp` crash-temporary form; all entries must be actual private current-owner single-link regular files with no symlink, hardlink, group/world mode or unsupported file shape. The original ciphertext size is capped at plaintext 64KiB + 6-byte magic + 12-byte nonce + 16-byte tag; an oversized orphan/temp is refused rather than silently accepted. Extra unreferenced private items are COUNTED as `unreferenced_items` but not validated as active, promoted, exported, or deleted; their value may be a legitimately retired blob, a pre-audit crash orphan or temporary. This intentionally is **not** forensic erasure classification or a complete file bundle. No new index was added and no production latency percentile over million-record archives was claimed.

For EACH current active reference, the original owner-only `LocalSecretStore::exists/get` verifies exact item presence, owner/private file custody, the existing unmodified authenticated encryption key/ref (AEAD AAD binding), nonempty value and (where present) original Queue body SHA-256. `Zeroizing` secret buffers are discarded immediately after inspection. A ciphertext that authenticates under the key but contains an intentionally different queued body is DENIED against immutable v33 Queue audit. The result is a limited non-secret **count summary**, never decrypted content, file paths or key material.
