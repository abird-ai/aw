## 2. Concrete defect reproduced BEFORE fix: final Turn could forge or omit receipts

The real `crates/aw-store/src/journal.rs::SessionHandle::append_sync` validates and serializes original `InvocationStarted/Finished`, `ToolStarted/Finished`, `ToolDenied` and tool argument revisions as bounded immutable `run_events`. AW-P6-10G/10H independently already enforce original unique/serial provider ordinal, response metadata-vs-outcome and no unknown-charge replay. But the final `persist_finish_in` accepted a **caller-provided `Turn`** merely if its ID, actor, prompt, model and profile matched the admitted original run; the `Turn.invocations`, `Turn.tool_records`, top-level `Turn.meta` and declared `Outcome::Completed` were **not checked against the immutable receipts**. A currently trusted low-level Session caller could finalize and attach a Turn that erased a paid provider call, inflated usage, swapped payer/model credentials via InvocationIdentity or rewrote an actually failed Tool into a success. This is an audit/receipt-integrity bug at the trusted local Store boundary, NOT proof of an external unauthenticated provider exploit or commercial duplicate charge.

## 3. One original immutable projection shared by finalization and crash recovery

**Only production code changed:** `crates/aw-store/src/journal.rs`. Added a small private `OriginalRunReceipts` projection and **one** `original_run_receipts(&Connection,run_id)` reader. It reuses the SAME existing immutable `run_events`, keyed by the original run ID, with `ORDER BY seq LIMIT 513` and an explicit **512-event maximum**, and reconstructs individual original `InvocationRecord` by ordinal, Tool denied/started/finished in original admission order, and bounded Assistant text. A `ToolRevised` alone never becomes a receipt; unknown originally started providers are conservatively `interrupted_unknown`, and a started Tool without a terminal receipt becomes `Interrupted` without fabricated output. This does NOT execute a model, Tool or Process, create another journal or copy private provider credentials. It is the already required **single original receipt projection**, now factored out of the existing crash-recovery algorithm rather than separately reimplemented in two security-sensitive places.

- Normal `persist_finish_in` first checks the original actor/prompt/model/profile as before, then **inside the SAME existing `BEGIN IMMEDIATE` final-result transaction** checks that the submitted `Turn.invocations` and `Turn.tool_records` serialize **byte-equivalently as complete typed records** to that immutable projection. An omission, extra fabricated record, changed actual Tool status/output, provider identity/account/payer, usage tokens, effect/site, receipt status/order or extra Tool success is denied **before** any final node insert, `llm_attempts` settlement or attachment. The comparison is typed-record serialization, not a raw model-supplied receipt key. The preexisting original `Turn` core structural validation also applies.
- A supplied `Turn.meta=Some(...)` must match the CompletionMeta of at least one genuinely journaled original provider `InvocationFinished`; no top-level usage inflation. `None` remains permitted when a result was interrupted/recovered or when the original immutable InvocationRecord carries the factual provider usage. A purported `Outcome::Completed` is refused while any original Tool/Provider started effect remains unfinished, or a terminal provider attempt was `failed_or_cancelled`, `stream_rejected` or synthetic `interrupted_unknown`. An original failed Tool with a genuine error receipt is still allowed to be explained by a subsequently successful model Turn if the original Agent actually recorded that continuation; the lower Store does not invent completion from the Tool alone.
- Startup/owner recovery now calls that SAME projection for the prior `run_events`, builds a **failed/inspection-required** Turn with original recorded receipts and Interrupted states, and calls the existing `persist_finish_in`/branch CAS. Recovery only replays evidence, never external paid/Tool/Process attempts. For rare owner recovery the bounded projection can be read again inside `persist_finish_in`, at most two scans of max512 events, rather than introducing a cache, duplicate ledger, reentrant authorization service, or unbounded persistence worker. Existing post-result-before-attach and killed-start crash tests remain the certification gate for factual-but-unattached receipts and no-replay.
- Importantly **do not compare arbitrary streamed `Turn.answer` or tool-visible Hook projections to journal Assistant text**: the original Agent can stream a partial response before the durable final Assistant exists, and typed Hook outputs are visible projections, NOT factual external effect receipts. The security contract enforced here is precisely original **provider and Tool receipts** and top-level provider metadata, not a speculative hardening that discards honest interrupted text or causes paid retry.
