### P2. Bounded SecretStore copy, exact own-key semantics and manifest

- Under the SAME original N exclusive vault fence, inspect only existing private `secrets/` and `secrets/items/`. If the original private `master.key` exists, copy its existing bytes to a newly created staged **0600** file; NEVER mint or rotate a new key to satisfy a backup. If ciphertext items/current refs exist but master is absent, fail closed. Stage original private ciphertext file bytes **without decryption/re-encryption**: ALL bounded canonical original `sec_<64 hex>.bin` items, including historical retired/unreferenced items, plus original explicitly shaped crash-temporary files. Preserve orphan facts for eventual operator review rather than deleting them. Always validate each source file through original platform owner-only/no-follow/single-link proof before copying; each destination uses `open_private_new`, bounded streaming and fsync. Source item size limited to original **64KiB plaintext + 6-byte header + 12-byte nonce + 16-byte tag**. Original O inspector checks actual active refs/AEAD and per-item source safety; the P copy adds no new decryption or authorization service.
- Enforce max **32,768 private items**, **512MiB** cumulative staged SQLite+private payload and a **bounded 8MiB manifest** (adequate for the maximum item count). Every file receives a private exact relative path, byte count and SHA-256 checksum inside a new owner-only `manifest.partial.json` created and fsynced LAST; the manifest's only accepted marker is **`aw-INTERNAL-PARTIAL-NOT-RECOVERABLE`**, and `complete` must be **false**. The manifest contains SQLite store identity/schema/application ID and original O active/unreferenced counts, NOT the plaintext secret, key bytes, provider account names, external grant/issuer/authenticator or anything intended for model/network release. These checksums detect accidental corruption **only**; they are NOT a signature, confidential archive encryption or trustworthy proof against malicious same-UID code.
- An internal verifier reopens the staged manifest and every staged file via original private-file checks, rejects unsafe/duplicate/traversing paths, malformed SHA-256 shapes, incorrect file digests/lengths, over-budget totals, missing SQLite, missing master for existing items, omitted/extra staged ciphertext, mismatched current inventory counts, bad SQLite schema/application/store ID or a manifest claiming `complete=true`. It does NOT advertise a validated stable restore format. The normal no-key unused vault remains without a new master. A final original O custody verification under the SAME unexpired maintenance token occurs before the returned ephemeral stage is considered internally coherent; a slow/stale/changed capture fails. The original `backup` lease is explicitly released whether the capture succeeds or fails, preserving the original paid/Tool no-replay and Process generation semantics.
- A private `PartialCapture` RAII scope owns the exact new `.partial` directory. On any error or normal scope exit, `Drop` removes only that owner-created directory after revalidating its private real-directory shape. A failure to delete is a quarantined incomplete `.partial` requiring owner inspection, NEVER automatically a complete backup. Source state and previous private backups remain unchanged. No final rename, stable data-format export, unsigned publication, external filesystem transfer or automatic restore is allowed in 10P.
